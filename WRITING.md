# Writing rules

How every reply, ticket, pull request description and message reads. The session-start hook
loads this whole file into every session, so it stays short; a rule only one skill needs
stays in that SKILL.md.

- Be concise and direct. Avoid unnecessary preamble or filler phrases.
- Prefer prose over bullet points unless a list is clearly the right format.
- Don't over-explain — trust the user's technical competence.
- When unsure, ask one focused clarifying question rather than multiple.
