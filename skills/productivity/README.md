# Productivity

Skills that aren't about shipping a change. Everything in `engineering/` moves a diff toward a
PR; these move *you* toward understanding something, and they're useful outside a code repo.

The slot for skills whose value isn't a commit — the boundary was worth having before there
were three of them, not after.

- **[explain](./explain/SKILL.md)** — Explain the thing you're stuck on — a block of code, a
  principle like CDN caching or hydration, a metric like LCP/CLS/INP, or how to build a
  specific thing with a specific product — in plain words that stay technically accurate,
  grounded in the real code or the real docs, and closed with an everyday analogy. It's worth
  reaching for even on questions that look answerable in one line, because the reflex answer
  to those is a definition made of more jargon.

- **[draft-reply](./draft-reply/SKILL.md)** — Turn a pasted thread, and usually a rough draft
  of the answer, into a reply that is short, checks out, and answers everything that was
  actually asked. The tightening is the easy part; the value is catching a number quoted from
  memory and the second question the draft never answered.

By role (see [`.agents/authoring.md`](../../.agents/authoring.md)), both are **atoms**:
explicit inputs, no instance-specific knowledge, callable by another skill.
